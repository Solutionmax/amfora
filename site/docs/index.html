Practical documentation for running Amfora and using it to send, collect and manage files.

01 / Start here

A private file workspace you operate

Amfora keeps file metadata in SQLite and stores objects through an S3-compatible storage layer. The image includes a private MinIO service for a zero-configuration starting point, and can use an external S3-compatible provider when that better fits your infrastructure.

Send

Upload files, create a share, and send a browser link. Add a password, expiry or view limit, and send recipient email notifications.

Receive

Publish a receive link so people can upload without an Amfora account. Set limits before sharing it.

Control

Manage users, folders, links, branding, two-factor authentication, and optional OAuth2/OIDC providers.

Data boundary. Amfora does not promise application-level encryption at rest. Protect the host volume or external storage account with the controls appropriate to your deployment.

02 / Install

Start with Docker Compose

You need curl, access to the private repository, Git, and Docker with Compose and Buildx 0.30 or later, plus Bash and a running Docker engine. Authenticate Git with an account that has repository access first. Run the one-line command from a directory without an existing amfora folder. Clone the maintained branch, build the application, and open the local web interface: 

curl -fsSL https://amfora.solutionmax.net/get | sh -s -- --docker

The installer script checks Docker, Compose, Buildx and source access before downloading anything. It creates an amfora directory, builds the image and starts Compose. Existing Amfora directories, containers or data volumes are refused. It does not install Docker, configure HTTPS, create backups or enable automatic updates.

To inspect the script before running it:

curl -fsSL https://amfora.solutionmax.net/get -o amfora-get.sh
less amfora-get.sh
sh amfora-get.sh --docker

The build script reuses layers in a dedicated Amfora builder and reclaims unused cache above a 4 GB target. Active builds can temporarily exceed that target. make clean only reclaims build cache; application data and images are retained. Keep the running image and a tested rollback image when upgrading.

Open http://localhost:5487. The first start creates the SQLite database, seeds configuration, and makes the first account created on an empty database an administrator. Later accounts are ordinary users unless an administrator creates or promotes them.

The sample Compose file publishes the web interface on 5487 and bundled storage on 9379. The API listens on 3333 inside the container and is left unpublished because the bundled web app reaches it through its server-side proxy.

Repository access. The Amfora GitHub repository is private. Arrange access through SolutionMAX before cloning. A 404 on the repository usually means your GitHub account has not been granted access.

For access from another computer, change STORAGE_URL from localhost to the storage address that computer can reach. For public use, complete the HTTPS setup below before sharing the instance.

03 / Production

Give the app and storage clear HTTPS addresses

Use a trusted reverse proxy for both the web interface and the browser-facing storage endpoint. A split-domain deployment can look like this: 

https://app.example.com    → container port 5487
https://files.example.com  → container port 9379

Set the values that describe that public arrangement:

environment:
  SECURE_SITE: "true"
  STORAGE_URL: "https://files.example.com"

STORAGE_URL is the URL used by a browser, not the address one container uses to reach another. The storage hostname must forward to the internal storage service and accept the browser’s upload and download requests. Keep the API on the private container network unless you operate another authenticated API client.

A minimal Caddy example

For Caddy running on the same host, bind the application ports to localhost in Compose. Replace the domains below with your own and point their DNS records at that host. 

ports:
  - "127.0.0.1:5487:5487"
  - "127.0.0.1:9379:9379"
app.example.com {
    reverse_proxy 127.0.0.1:5487
}
files.example.com {
    reverse_proxy 127.0.0.1:9379
}

The product website at amfora.solutionmax.net is separate from your Amfora application. These example domains do not provide a hosted Amfora service.

Forward the original host and protocol through the proxy. SECURE_SITE=true enables secure cookies. Configure HSTS at your HTTPS reverse proxy. Set TRUST_PROXY=false when the API is exposed without a trusted proxy in front of it.

04 / Storage

Choose bundled or external S3-compatible storage

Bundled storage

Leave ENABLE_S3=false (the default) to run the included MinIO service. Set STORAGE_URL to the public URL that browsers can reach. The Compose example uses http://127.0.0.1:9379 for local use. The bucket is private and the container writes its generated credentials under the persistent application directory.

External storage

Set ENABLE_S3=true and provide the external endpoint and credentials. The endpoint and bucket must be reachable and permitted for the browser requests represented by generated upload and download URLs. 

ENABLE_S3=true
S3_ENDPOINT=s3.example.com
S3_PORT=443
S3_USE_SSL=true
S3_ACCESS_KEY=your-access-key
S3_SECRET_KEY=your-secret-key
S3_REGION=us-east-1
S3_BUCKET_NAME=amfora-files
S3_FORCE_PATH_STYLE=false

Use S3_FORCE_PATH_STYLE=true for providers such as MinIO. If a provider rejects the SDK checksum, set S3_DISABLE_CHECKSUMS=true as documented by that provider. Keep S3_REJECT_UNAUTHORIZED=true unless you have a deliberate certificate exception.

Limits and URL lifetime

A new installation seeds a 1 GiB maximum file size and 10 GiB maximum storage per user. Administrators can adjust those values in Settings. PRESIGNED_URL_EXPIRATION controls the default generated storage URL lifetime in seconds and defaults to 3600.

05 / Daily work

Send a link or collect files through a form

Your workspace

The application opens at sign-in, or your dashboard when you are already signed in. The dashboard gives you a starting point for files, shares and upload requests. Use folders to organize files before creating a share. Profile manages your personal details and account security; administration controls are available to administrators.

Send files

  1. Sign in and open My files.
  2. Upload files or create folders.
  3. Select the items, create a share, and set its restrictions.
  4. Copy the generated /s/<alias> link.

A share can have a password, expiration date, maximum view count, and recipient email notifications. Recipient entries do not restrict access to a public share. Its owner can later edit the contents, notification recipients, password, expiry, or alias from Shares. A recipient opens the link in a browser; a protected share asks for its password before files are available.

Copy a link or export its QR code

Use the share menu to copy its link. Open the QR-code action to display or download a PNG that points to the same URL. After changing an alias or application hostname, generate a new QR code and replace any older copies. Anyone with the link or code can reach the share, subject to its restrictions.

Receive files

  1. Open Receive files and create a receive share.
  2. Choose optional file count, size, type, password, expiry, name, and email requirements.
  3. Copy the generated /r/<alias> link.

The sender uploads from the public receive page without an Amfora account. The owner reviews the received files in Reverse shares.

06 / Administration

Keep access and identity in the workspace

Administrators can invite users, list and deactivate accounts, change roles, set storage limits, customize the installation, configure SMTP, and manage external login providers. Invite links are one-time registration links.

Make it feel like your brand

Open Customization to set the application name, logo, accent color, font and corner radius. Check the result in both light and dark themes, on mobile, and on a public upload and download page. Use Settings for storage limits, language, email and authentication configuration.

Two-factor authentication

Each user can enable TOTP in their profile, verify setup with an authenticator, save backup codes, and remove trusted devices. A 2FA login verifies the password first and then accepts a TOTP or unused backup code.

OAuth2 and OIDC

External login is optional. The seeded providers are Google, Discord, GitHub, Auth0, Kinde, Zitadel, Authentik, Frontegg and Pocket ID. Additional compatible OIDC providers can be configured. Match callback URLs and client settings at both ends. Keep password authentication enabled until an external provider has been tested; disabling it also disables password reset.

Password recovery

Password reset requires password authentication and a working SMTP configuration. Responses deliberately do not reveal whether an email address exists. For operator recovery, the container includes an interactive reset tool: 

docker compose exec amfora sh -lc 'cd /app/amfora-app && ./reset-password.sh'
docker compose exec amfora sh -lc 'cd /app/amfora-app && ./reset-password.sh --list'

07 / Operate

Back up before you upgrade

Bundled storage backups

Back up the complete persistent /app/server directory, including prisma/amfora.db, minio-data, and generated storage credentials. Stop the container or use a filesystem snapshot consistent for the database and objects.

External storage backups

Back up the SQLite database and the external S3 bucket through that provider’s supported process. Keep the database and object backup points close enough to restore a consistent workspace.

Upgrade

Keep the persistent volume, replace the image, and start the container. Startup applies the Prisma schema and seeds missing configuration/provider records. Older database filenames are migrated to prisma/amfora.db; an existing internal bucket is preserved when no explicit bucket override is supplied. Verify a test share and download after the upgrade.

08 / Troubleshooting

Check the boundary where the request stops

The page loads but uploads fail.
Confirm that STORAGE_URL is browser-reachable, forwards to the storage service, and accepts the storage requests. Then inspect docker compose logs -f amfora.
The API starts but storage is unavailable.
For bundled storage, wait for initialization and check for .minio-credentials in the persistent directory. For external S3, verify every S3_* value and bucket permission.
HTTPS redirects or cookies behave incorrectly.
Check the forwarded host and protocol, set SECURE_SITE=true for HTTPS, and set TRUST_PROXY=false when no trusted proxy is present.
Password reset email does not arrive.
Enable SMTP in Settings, verify the host, port, credentials, sender, and TLS mode, and run the admin SMTP test action.
An upgrade appears empty.
Check that the original persistent volume is mounted. Do not create a new bucket or rename the storage directory by hand; preserve the bucket recorded in .minio-credentials.

09 / About Amfora

A self-hosted workspace for the handoff.

Amfora is a self-hosted file workspace for sending files, collecting uploads, and managing access. This guide covers the installation, storage, sharing, and administration workflows that keep a handoff moving.
